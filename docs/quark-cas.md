# 夸克 / UC 网盘 CAS 使用说明

> 适用驱动：`Quark`（夸克网盘）、`UC`（UC 网盘）
> 底层实现：`drivers/quark_uc/`（一份代码注册两个驱动，接口一致）

## CAS 是什么

CAS 是一个**占位文件**，本身只有几百字节，记录着真实文件的元数据（文件名、大小、MD5、SHA1）。

它的价值在于：网盘普遍有"秒传"机制——当你上传一个文件时，服务端先比对哈希，如果云端已存在相同文件，就不传字节，直接生成一个文件引用。CAS 正是利用这一点：

1. 文件正常上传一次（真实占用空间）
2. 生成 `.cas` 占位文件，删除原文件
3. 需要播放时，读 `.cas` → 拿哈希去秒传 → 真实文件"凭空"回来 → 取直链播放 → 删掉临时文件

**净效果**：目录里只留一个几百字节的 `.cas`，空间占用归零，需要时零流量还原。适合影视库这类"存得多、看得少"的场景。

对应的官方实现见 139 云盘驱动（`drivers/139/cas.go`），本驱动是同一套机制在夸克上的移植。

## 配置项

管理后台 → 存储 → 添加/编辑夸克网盘，会看到以下开关：

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `generate_cas` | 关 | 上传完成后，在同目录生成同名 `.cas` 占位文件 |
| `delete_source` | 关 | 生成 `.cas` 后删除已上传的源文件 |
| `restore_source_from_cas` | 关 | 上传 `.cas` 文件时，自动还原为真实文件而非存储 `.cas` |
| `cas_ext_allowlist` | 空 | 扩展名白名单，留空表示全部允许。例：`mp4,mkv,iso,zip` |
| `cas_download_restore` | 关 | 开启后通过 `/d/*` 下载 `.cas` 会还原并返回真实文件 |
| `cas_delete_permanently` | 关 | 删除源文件时尝试绕过回收站，失败自动回退普通删除 |
| `use_play_direct_link` | 关 | 视频播放（含 CAS 还原播放）优先走网页端原画播放接口，获取免 Cookie 直链供 OpenList 302 直连，不再本机代理转流；拿不到原画自动回退代理模式 |

配置语义与 139 驱动完全一致，无需重新学习。

### 关于 302 播放与卡顿

夸克/UC 驱动的下载直链附带 Cookie，OpenList 只能**代理转发**（服务器流量=播放流量），人多或机器弱时会卡。改善方式按优先级：

1. **`use_play_direct_link`（推荐先试）**：走网页播放器同款接口 `/file/v2/play`，返回的 CDN 直链不带 Cookie，OpenList 可直接 302 让播放器直连夸克 CDN。仅取**原画**档并校验字节数与源文件一致，非原画自动回退代理，不会偷偷降画质。注意：该接口行为未经官方保证，若实测无法播放请关闭。
2. **转码播放**：`use_transcoding_address`（仅 Quark）。可 302 但播放的是转码流，画质有损。
3. **两者同时开启时**：优先原画直链，失败回退转码，再失败回退下载直链。

## 推荐配置

**影视库（最典型场景）**

```
generate_cas            = true
delete_source           = true
cas_ext_allowlist       = mp4,mkv,avi,mov,ts,wmv,m4v
cas_delete_permanently  = true   # 可选，见下方注意事项
```

白名单建议只填媒体扩展名——避免给小文件也生成一份 `.cas`，徒增文件数量却没有收益。

**只播放、不删源文件**：`generate_cas = true`，`delete_source = false`。源文件保留，`.cas` 作为冗余副本，安全但不省空间。

## 工作原理

夸克的秒传链路是 **MD5 + SHA1**（与 115 的 `sha1 + preID`、139 的 `sha256` 不同），因此 CAS 负载中记录的是这两个指纹。

**生成**

```
正常上传文件 → 得到 md5 / sha1
            → 连同文件名、大小、provider=quark 编码为 base64
            → 作为 xxx.cas 文本文件上传到同目录
```

**还原（零流量）**

```
读取 .cas 得到元数据
  → 用仅携带元信息的空流调 /file/upload/pre 拿 task_id
  → 调 /file/update/hash 提交 md5 + sha1
  → 服务端命中即 finish=true，文件凭空出现
  → 返回 fid
```

**播放**

`Link` 收到 `cas_video` 请求 → 在根目录 `TEMP` 文件夹还原临时文件 → 取直链 → **异步删除**临时文件。全程不传输文件字节。

## 注意事项

1. **`cas_delete_permanently` 是非官方用法**。夸克 `/file/delete` 接口的 `action_type=1` 是进回收站（OpenList 原生行为），社区脚本中存在 `action_type=2` 绕过回收站的写法。开启后先试 2、失败自动回退 1，不会比默认更糟，但**效果需自行实测确认**。播放产生的临时文件则总是优先尝试彻底删除，避免每播一次就往回收站塞一份大文件。

2. **秒传必须 MD5 和 SHA1 同时命中**。云端不存在该哈希时会明确报错 `source file data does not exist in cloud`，不会静默失败。

3. **还原仍需剩余容量**。虽然不传字节，还原出的真实文件会计入网盘容量，容量不足会失败。

4. **CAS 与源文件二选一**。开了 `delete_source` 后源文件就没了，如果后续秒传失败，文件不可恢复。**建议先小范围验证秒传确实可用，再批量开启。**

5. **生效范围**：仅 `Quark` 和 `UC` 两个驱动。`QuarkOpen`（夸克开放平台）、`QuarkTV`、`UCTV` 是独立的驱动包，且存在技术障碍无法适配：

   - **QuarkTV / UCTV**：只读驱动（`Put` 直接返回 `errs.NotImplement`），不支持上传，也就没有"生成 CAS"和"秒传还原"的基础。
   - **QuarkOpen**：开放平台的 `upload_pre` 要求 `proof_code1/2`——从文件指定偏移读取 8 字节做 base64（反作弊校验）。而 CAS 还原的场景恰恰**没有文件字节**，proof 无法生成，秒传请求会被拒绝。除非夸克官方放开 proof 校验，否则此路不通。

## 与 139 CAS 的差异

| | 139 | 夸克 / UC |
| --- | --- | --- |
| 秒传指纹 | SHA256 | MD5 + SHA1 |
| 大文件恢复 | 需 PC 头（>50GiB） | 无此限制 |
| 彻底删除 | 官方接口支持 | 需 `cas_delete_permanently`（非官方） |
